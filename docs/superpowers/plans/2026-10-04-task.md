# TASK implementation plan

**Goal:** Build the supplied TASK V1 as a working local application with a PostgreSQL production path.
**Architecture:** Next.js route handlers call permission-aware domain services backed by Drizzle. HR stays behind an adapter. The client renders the same records in all views.
**Spec:** ../specs/2026-10-04-task-design.md
**Execution:** Inline, following the user's instruction to proceed.

## Global constraints

- No fake metrics or separate HR passwords/hierarchy.
- Production must not accept development identities.
- Private tasks never leak to managers; all mutation authorization is server-side.
- English/Arabic, RTL/LTR, keyboard focus and responsive shell.

## Review focus

- Nonmembers guessing identifiers: service tests must deny both reads and writes.
- Partial multi-assignee completion: test aggregate status and reopening.
- Reporting changes: validate against fresh HR direct reports at mutation time.
- Child tasks and attachments: inherit parent visibility; no private-work leakage.
- Concurrent updates: transactions lock tasks and preserve independent completions.
